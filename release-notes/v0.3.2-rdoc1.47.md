# v0.3.2 — MCP protocol version negotiation fix

**Date:** 2026-11-23

## Highlights

- `initialize` no longer rejects clients on a newer MCP protocol revision, so
  clients that send `2025-11-25` (opencode 1.18+) can connect again

## Fixes

- **Protocol version negotiation in `initialize`** (`src/mcp/mcp_server.cpp`)

  The server hard-coded `2025-03-26` and answered every other request with a
  JSON-RPC error, which killed the connection during the handshake:

  ```
  MCP error -32602: Unsupported protocol version: 2025-11-25
  (server supports 2025-03-26)
  ```

  The MCP lifecycle spec requires the opposite: when the requested revision is
  not supported the server MUST reply with one it does support and leave the
  decision to the client. Newer revisions only add optional capabilities
  (structured tool output, elicitation, tasks), so a tools-only server stays
  wire-compatible with them.

  The server now advertises `2025-11-25` / `2025-06-18` / `2025-03-26` and
  echoes the client's revision when it is in that list, falling back to the
  latest supported one otherwise.
